# Qwen3-ASR-1.7B 方言地址识别

> 用 Qwen3-ASR-1.7B 做方言语音里的地址识别。
> 本仓库是一套**零训练**方案：模型只负责"听音"，地址库负责"定字"；
> 在方言各自的音系空间里做检索，用两遍解码把候选喂回模型，最后用带先验的打分函数排序、三道阈值兜底。
> 附带一个能直接录音的测试界面和一套按难点分层的评测。
> 完整的推理过程（为什么这么设计）见 [docs/思路推演.md](docs/思路推演.md)，
> 分模块速查见 [docs/技术方案与思路.md](docs/技术方案与思路.md)，文档导航见 [docs/index.md](docs/index.md)。

## 一句话思路

要的不是 ASR 在做的 `argmax P(文字|音频)`，而是 `argmax P(真实地址|音频)`：

```
P(A|x) ∝ P(x|A) · P(A)
           ↑声学似然   ↑地址先验 —— ASR 完全没有这一项
```

ASR 把"武侯区"听成"五后区"，不是听错了，是它的语言模型先验是通用中文，
低频专名天然吃亏。解法不是修 ASR，是把 `P(A)` 补进来——地址库 + 层级约束 + 用户定位。

而方言误识有个救命的性质：**错的是字，音基本还在**。

| | 内容 | 拼音 |
|---|---|---|
| 真值 | 成都**武侯区红牌楼** | wu hou qu hong pai lou |
| ASR | 成都**五后区红排楼** | wu hou qu hong pai lou |
| 汉字距离 | 0.50 | 拼音加权距离 **0.00** |

所以匹配在**音的空间**做，不在汉字空间做。

## 22 种方言怎么覆盖

模型卡列出 22 种中文方言。它们**不是**都能用普通话拼音近似——粤语有 -p/-t/-k 入声和 6~9 个声调，
拿普通话拼音量粤语误识等于用错坐标系。按音系分三类路由：

| 类别 | 方言 | 音系空间 | 库 |
|---|---|---|---|
| 官话系（12） | 四川 贵州 云南 湖北 河南 陕西 甘肃 宁夏 东北 河北 天津 山东 | 普通话拼音 + **方言音变代价矩阵** | pypinyin |
| 过渡区（2） | 山西（晋语） 安徽 | 普通话拼音 + 对应官话矩阵 | pypinyin |
| 非官话·有库（4） | 粤语港 / 粤语广 / 闽南 / 福建 | **粤拼** / **台罗** + 各自音系的懒音矩阵 | pycantonese（可选，未装则降级）/ taibun（已验证） |
| 非官话·无库（4） | 吴语 浙江 湖南（湘） 江西（赣） | 普通话近似（弱信号） | — |

三条路径**并联**：拼音能救的用拼音，有专用库的用专用库，全都不行时靠**上下文注入 + 声学重打分**兜底——
模型本身就在这 22 种方言上训练过，它的编码器懂粤语音系，我不需要在外面用错误的坐标系去猜。

另外方言差异不止发音，还有**词汇**（粤语"喺"=在、"屋企"=家；闽南"阮兜"=我家；四川"屋头"=家）。
地址领域用到的方言词是**封闭集**（居所词/方位词/量词/数字读法，几百条量级），所以做成确定性查表，不交给 LLM 猜。

## 流水线

```
音频
 ↓  Qwen3-ASR 第 1 遍：裸转写 + 方言标签
粗文本
 ↓  dialect_lexicon   方言词 → 标准中文（喺→在、屋头→家、噻→删）
 ↓  normalize         口语数字 → 阿拉伯数字（幺零幺→101、二零一→201、三十→30、八百八→880）；剥离门牌/楼栋/单元/室
                      位值不递减的非法串（ASR 听错的"八百一百八"）不算、原样保留并标 unverified，门牌绝不猜
地名部分 + 门牌字段
 ↓  romanize          按方言选音系空间（拼音 / 粤拼 / 台罗）
 ↓  rank              滑窗对齐找命中 → 自底向上回溯父链 → 打分 → 决策
候选链 Top-K
 ↓  Qwen3-ASR 第 2 遍：把 Top-K 写进 system prompt 重新解码（可开关）
 ↓  取两遍中决策更强的一方
规范地址 + 结构化字段 + N-best
```

**打分函数**（`rank.py`）：

```
score(A) = 0.50·音相似度 + 0.20·文本覆盖率 + 0.15·地址先验 + 0.15·证据深度 − 0.25·行政区冲突
```

层级合法性是**硬约束**：候选链一律由"路→区→市→省"回溯父链生成，"成都市+江北区"这种链根本不会被构造出来。

**三道兜底**（防"自信地答错"）：
1. Top-1 与 Top-2 指向不同行政区且分差 < 0.06 → `ambiguous`，吐 N-best 让人确认
2. Top-1 音相似度 < 0.62 → `reject`，保留原文
3. 门牌/单元/室号**绝不从地址库猜**，只走纯规则抽取

### 环境要求

| 项 | 要求 |
|---|---|
| Python | **3.10 ~ 3.12**，推荐 3.12。3.13+ 未验证 |

### macOS（Apple Silicon）

```bash
python3.12 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt        # torch 会自动装到 MPS 可用的版本
```

Apple Silicon 上会自动走 MPS，M 系列芯片单句推理约 0.4~2.2 秒。

### Windows

torch 要单独装，**PyPI 上的默认轮子是纯 CPU 版**，有 N 卡的话必须指定 CUDA 源。

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\activate

# 有 NVIDIA 显卡（把 cu124 换成你的 CUDA 版本）
pip install torch --index-url https://download.pytorch.org/whl/cu124
# 没有独显，纯 CPU
pip install torch

pip install -r requirements.txt
```

两个 Windows 专有的注意点：

- **控制台编码。** 脚本会打印 `✓` 和中文。把输出重定向到文件时（`> report.txt`），中文 Windows 默认用 GBK，`✓` 编不进去会报 `UnicodeEncodeError`。先执行 `chcp 65001`，或者设 `set PYTHONIOENCODING=utf-8`。
- **纯 CPU 很慢。** 1.7B 模型在 CPU 上跑 fp32，单句要几十秒，内存吃到 7 GB 左右。只想看后处理效果的话用上面的文本模式，不要下权重。

### Linux

和 Windows 一样单独装 torch（CUDA 源同上），其余相同。

<details>
<summary>备选路径：已经有非 -hf 版权重时的转换办法</summary>

官方发了两套权重。`Qwen3-ASR-1.7B` 是 qwen-asr 包和 vLLM 用的 `thinker.*` 布局，transformers 原生类加载不了；`Qwen3-ASR-1.7B-hf` 是原生布局，张量内容完全相同。

如果你已经下了非 `-hf` 版，可以本地转换，省一次 4.7 GB 下载：

```bash
python scripts/verify_model.py     # 校验大小 + safetensors 头部 + sha256
python scripts/convert_to_hf.py    # 纯键名重命名，708/708 键 + 形状双校验，约 1 秒
```

两个前提：

1. 转换脚本需要 `models/_hf_ref/` 下的 4 个配置文件（`config.json`、`generation_config.json`、`chat_template.jinja`、`processor_config.json`），它们来自 `Qwen3-ASR-1.7B-hf` 仓库，共 16 KB。用 `hf download Qwen/Qwen3-ASR-1.7B-hf --include "*.json" "*.jinja" --local-dir models/_hf_ref` 取。
2. **转换不删源，磁盘要占两份，约 10 GB。** 直接下 `-hf` 版只要 4.4 GB。

`verify_model.py` 里的 sha256 是 2026-09-09 的上游快照，Qwen 若重新上传会校验失败，那时改用文件大小核对即可。
</details>

## 常见问题

**录音全是静音，模型返回空串。** 装了 BlackHole、VB-Cable 这类虚拟声卡时，系统默认输入常被它占用，录出来是全零音轨，看起来像「识别不准」，其实是没收到声音。界面会显示当前输入设备和实时电平，自动跳过虚拟设备，两路采集都静音时直接给诊断。手动选一个真实麦克风即可。

**本地接口连不上或测试全红。** 如果开了代理软件的 TUN 模式，`127.0.0.1` 可能被劫持。跑测试时带上 `no_proxy=127.0.0.1,localhost`。

**上传 webm/m4a 报错要 ffmpeg。** 浏览器直传 wav 不需要 ffmpeg，只有 MediaRecorder 回退路径要转码。macOS `brew install ffmpeg`，Windows `winget install Gyan.FFmpeg`。

**`.m4a` / `.aac` 评测文件读不出来。** `eval/run_eval.py` 的扩展名列表里写了这两种，但 librosa 新版去掉了 audioread，实际解不了，任何平台都一样。先用 ffmpeg 转成 wav。

**粤语走的不是粤拼。** 粤拼依赖可选包 `pycantonese`，没装时自动降级到「普通话拼音·粤语近似」并在 `/api/status` 里报出原因。台罗（闽南语）依赖 `taibun`，已验证可用。降级不影响主链路。

## 评测

评测集 `data/eval/xinan_guanhua.json`：24 句西南官话地址，11 个难点维度（同音异形 / 方言词 / 口语数字 /

按难点标签分层，另报错误严重性分级（行政区错 = 严重）。

| 行政区三级全对 | 100% |

## 已知边界（诚实标注）

- **上下文注入**：开源版 README 没有 "context" 字样，这个能力是从 `chat_template` 结构推断的（system 位是自由文本，直接进 Qwen3 解码器，文本侧 65536 上下文）。做成可开关，实测记录见下。
- **离线地址库**：省/市/区三级全国全量（3214 条，来自 cpca 的 adcodes.csv），路级是精选 347 条——路级只能靠 POI API 覆盖（接口已留）。adcode 依据 GB/T 2260；民政部自 2026 年起不再单独公布区划代码，上线前应对照国家地名信息库核对撤县设区等变动。库里没有的路/小区按 ASR 原文保留并标"未核验"，不吞、不编。
- **吴语/浙江/湘/赣没有成熟罗马化库**，这 4 个方言的音系路径只是普通话近似，准确性主要靠上下文注入和模型自身的方言能力（山西/晋语走中原官话矩阵，在过渡区）。
- **粤拼路径未经端到端验证。** `pycantonese` 在作者机器上因网络问题始终没装上，粤语实际走的是「普通话拼音·粤语近似」降级路径。降级机制本身验证有效（`/api/status` 会报 `粤拼 available=False`），但粤拼相对降级路径的增益没有数据。台罗（闽南语）已装并验证可用。
- **声学重打分**（用 Qwen3-ForcedAligner 对候选做对齐打分）是方案里方言无关的终极兜底，本仓库未实现，只列为下一步——需要再下 0.6B 权重。

## 实测记录

**2026-09-09 · Apple M5 Pro / MPS fp16 / transformers 5.16.1**

| 项 | 结果 |
|---|---|
| 权重加载 | 0.9~2.9s（转换后原生加载） |
| 单句推理 | 0.4~2.2s（首句含预热） |
| 输出格式 | `language Chinese<asr_text>正文`，语种标签在前 |
| 粤语输入 | 标签 `Cantonese`，**输出粤文**（"我住喺广州市…"）→ 词汇归一层把 喺→在 |
| 上下文注入（正确候选） | 输出不变（本来就对） |
| 上下文注入（**误导候选**，某些组合） | 输出从「红牌楼」变成「**红牌坊**」 |

**system prompt 里的候选确实会改变开源 1.7B 的解码结果**，既证明两遍解码这条路通，
也证明"幻觉性纠正"的风险是真的。但触发条件不规律，六组对照见
[`eval/reports/context_injection.json`](eval/reports/context_injection.json)：

| 注入 | 输出 |
|---|---|
| 不注入 / 单条误导候选 / 两条都指向红牌坊 / 只给一个无关候选 | 红牌楼（未被带偏） |
| 误导候选 + 花牌坊街 | **红牌坊** |
| 误导候选 + 春熙路 | **红牌坊** |

单条误导候选顶得住，两条指向不同地点时反而翻车，规律尚未解释清楚。
效果真实但不单调，这就是打分层三道阈值存在的理由，也是第二遍结果不能无条件采信、
要和第一遍比决策等级再择优的原因。

> 早期记录曾写作"塞一条误导候选就把红牌楼改成红牌坊"，2026-09-09 复跑未能复现单条即翻的情形，已按实测更正。

MPS 上一个必踩的坑：processor 输出的梅尔特征是 float32，模型是 float16，`generate` 前要手动把浮点张量
cast 到模型 dtype（`asr.py` 已处理），否则第一层 conv2d 报 `Input type (float) and bias type (c10::Half)`。

**2026-09-09 · 第一条真人四川话录音（7.8s，MacBook 内建麦克风）**

| 环节 | 结果 |
|---|---|
| ASR 第 1 遍 | `成都市花牌坊**高通巷**三十八号碧园公寓二栋四单元六零三` |
| 真实地址 | 成都市花牌坊**交通巷**38号碧园公寓2栋4单元603 |
| 误识类型 | 交 jiao → 高 gao：西南官话**见系不颚化**（街=gai、交=gao、鞋=hai） |
| 检索层 | 补入 g/j、k/q、h/x 三对音变后，交通巷↔高通巷 距离 0.067，命中 |
| 最终输出 | `四川省成都市金牛区花牌坊街交通巷38号碧园公寓2栋4单元603室` · confident |

这一条暴露了两个问题，都已修：

1. **音变矩阵漏了见系不颚化**。这是西南官话最典型的音变之一，第一版只收了 n/l、平翘舌、h/f、前后鼻音。
2. **拼装层会吞掉没命中的地名**。第一版是"从候选链生成"，只输出命中的层级——地址库里没有"碧园公寓"，
   它就消失了，用户看到的是 `四川省成都市38号2栋4单元603室`。现在改为**以 ASR 原文为锚**重建：
   命中段换规范名、参照地标删掉、缺失的上级行政区补插、**没命中的段原样保留并标"未核验"**（界面上橙色虚线）。
   宁可把没核验的原文交出去并标明，也不能悄悄吞掉。同时新增 `partial` 决策：只命中省/市级不再算 confident。

**2026-09-09 · 全国省市区三级入库后的三条规则**

手工精选 27 个城市在真人测试里立刻穿帮（"南阳市卧龙区"落空）。改为全国 34 省 / 337 市 / 2843 区县全量入库
（`data/addresses/raw/adcodes.csv`，含经纬度），路级仍是精选。库大 6 倍后暴露的问题都是**2 字名撞车**：
"中山路"的中山→中山市、"广场"→广昌县（guang chang）、"河南话"的南话→南华县、"阳河"→唐河县。规则：

| 规则 | 内容 | 挡住的案例 |
|---|---|---|
| 弱命中 | ≤2 音节的命中标 weak：不能单独成链、不当冲突扣分、不触发落选删除 | 中山市 / 广昌县 / 南华县 |
| 别名不担保 | 链的最深命中若靠 2 字**别名**撞上，链不成立——父级强命中不能替它担保（南阳市下 12 个县随便哪个都能被"印证"） | 唐河县←"阳河" |
| 孤立路名须精确 | 没有任何行政区命中的链，路名距离必须 ≤0.15——全国重名路太多，无城市锚定时 ±1 宽度容错就是在猜 | 民权路←"人民路" |
| 方言/籍贯后缀 | **别名**后紧跟 话/腔/人 不算地址（河南话、武汉腔、四川人）；全名不受影响（"卧龙区人民路"的区+人） | 河南省←"河南话" |

副产品：全国重名区（鼓楼区×4、西湖区×2）只说区不说市时正确地弹 `ambiguous` 让人确认，说了市就分开。
路级自动别名也改为只生成 ≥3 字（"人民广场"不再产生"人民"）。

测试界面最上方改为**两栏对照**：左「原始模型」= 第 1 遍裸转写（messages 里只有音频，无 system prompt、
无语种强制、不连地址库），右「改造后」= 本方案输出。一眼就能看出后处理层到底改动了什么。

另一个和模型无关但会让人误判的坑：机器上装了 BlackHole 之类的**虚拟音频设备**时，浏览器可能把它当默认输入，
录出来全是零，模型返回空串——看起来像"识别不准"，其实是没收到声音。测试界面现在会显示当前输入设备和实时电平，
自动跳过虚拟设备，并在两路采集都静音时直接给诊断而不是上传。
