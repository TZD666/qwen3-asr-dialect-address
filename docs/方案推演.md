# 方言地址识别方案推演

> 这份文档记录整套方案是怎么一步步推出来的：先摸清模型能力边界，再从它的错误模式反推该补什么，最后落到具体的检索、打分与拒识设计。每个数字都可以在仓库里复现。

## 1. 先明确模型的能力边界

拿到任务后，先评估 Qwen3-ASR-1.7B 的能力边界，避免后续设计要么解决不存在的问题，要么依赖模型不具备的能力。
模型官方指标如下：
| 测试集 | 词错率（CER） |
|---|---|
| AISHELL-2（普通话朗读） | 2.71% |
| Fleurs-zh | 2.41% |
| WenetSpeech（网络 / 会议） | 4.97% / 5.88% |
| KeSpeech（多方言普通话） | 5.10% |
| WenetSpeech-Chuan 难集 | 21.63% |
| 22 种方言对话集 | 15.94% |

普通话朗读场景词错率约 3%，而方言自由对话高达 16%。一条地址约 20 字，按 16% 计算平均错 3 字以上。地址容错为零，少数字错误就可能导致投递失败。因此，核心难点不是把整体错误率再压低几个百分点，而是针对那少数错误字做有效纠正。

## 2. 方言标签需做音系映射，不能直接使用

模型支持 22 种方言，列表前 18 项多为省份名（四川、河南等），后 4 项才是语言学方言名（粤语、吴语、闽南语）。这种划分与真实音系并不对齐。例如“四川话”和“吴语”处于不同分类维度，前者属官话，后者属吴语区。
从音系差异看：四川话“武侯区”读作 wu hou qu，与普通话拼音高度一致；而粤语“广州”读作 gwong zau，“番禺”读作 pun jyu，且存在普通话没有的 -p、-t、-k 入声韵尾。因此，用普通话拼音去衡量粤语转写的正确性，会系统性地误判。
所以我的第一个设计决策是：不能直接使用模型给出的方言标签，必须自行建立从 22 个标签到实际音系空间的映射表。官话系使用普通话拼音，粤语使用粤拼，闽南语使用台罗拼音，吴语、赣语、湘语等暂无成熟罗马化方案，暂时使用普通话近似，山西、安徽作为过渡区处理。

## 3. 模型架构决定其行为特征

查看模型配置和代码后，其结构如下：
音频 → 24层音频编码器（128维梅尔特征，d_model=1024）
↓
28层 Qwen3 文本解码器（hidden=2048，词表15万，上下文65536）
↓
"language Chinese<asr_text>正文"
关键在于解码器是一个通用 Qwen3 语言模型，而非专用音素解码器。这意味着每一步解码，模型都在声学证据和语言模型先验之间做权衡。例如，“武侯区”的声学信号是 wu hou qu，但语言模型认为“五后区”比“武侯区”更常见（专名低频），于是输出“五后区”。模型并非听错，而是选字时先验压过了声学证据。
这一认识也提示我们：先验分布可以通过 system prompt 或上下文注入来调整——模型卡虽未明确提及 hotword 机制，但从模板结构推断该通道存在，需要实测验证。

## 4. 实测输出呈现不同的正字法

用真实录音测试后发现输出格式有以下特征：
普通话录音：输出简体中文，语种标签为 Chinese。
例：“我家在成都市武侯区红牌楼街道二环路南四段三十号。”
粤语录音：输出粤文，语种标签为 Cantonese，部分用字不同（如“在”写为“喺”）。
例：“我住喺广州市天河区体育西路一百零三号。”
闽南/台湾腔录音：标签仍为 Chinese，但输出繁体中文。
例：“好，你聽好啦！厦门市思明區鼓浪嶼龍頭路八十九號……”
这说明模型将语音内容渲染为相应的书面语形式，而非逐字音素转写。下游处理必须兼容简体、繁体、粤文三种正字法，并处理“喺”“厝”“嘅”等方言特有字。

## 5. 问题形式化

ASR 的目标是：
argmax P(文本 | 音频)
而我们的目标是：
argmax P(真实地址 A | 音频 x)
展开为贝叶斯形式：
P(A|x) ∝ P(x|A) · P(A)
ASR 模型对前一项（声学似然）处理得较好（CER 2%~5%），问题出在后一项：模型使用的先验是 P(通用中文文本)，而我们需要的是 P(真实存在的地址)。两者分布差异很大，专有地名在通用语料中低频，常见词容易覆盖长尾。
因此，补救方向不是提升声学能力，而是替换先验。先验可以离线构建为一张地址清单，无需重新训练模型。

## 6. 错误往往在字不在音

两条典型真实录音验证了这一点：
天津话录音：模型输出“天津和平区滨江道一百六十八号全叶厂十四楼”，实际应为“劝业场”。
拼音对比：quan ye chang vs quan ye chang，拼音距离 0.000，汉字全错。
成都话录音：模型输出“花牌坊高通巷三十八号”，实际应为“交通巷”。
拼音：gao tong xiang vs jiao tong xiang，拼音距离 0.067。
原因在于西南官话见系不颚化，普通话中 g/k/h 在细音前颚化为 j/q/x，而方言保留古读（如“街”读 gai，“交”读 gao）。这是系统性音变，非随机错误。
同时，繁体/简体在拼音空间距离为零（如“廣州”与“广州”），正字法差异在音层自动消解。因此，选择拼音作为匹配基座是合理的。

## 7. 音距离需加权设计

标准编辑距离将每个替换视为代价 1，无法区分系统性音变与随机混淆。我们引入加权的替换代价矩阵，令：
cost(a → b) 与 P(a 被听成 b) 成反比
具体设值：n/l 互换 0.10，平翘舌 0.12，前后鼻音 0.08~0.12，见系不颚化 0.20，浊音清化 0.35。目前为手设近似值，覆盖 20 条声母规则和 26 条韵母规则，并标注适用方言区。理想情况下应由标注数据统计混淆概率取负对数，现阶段用作合理近似。
距离计算分两层：外层在音节序列上做对齐，内层计算声母+韵母代价。若将整串拼音拼接后算编辑距离，会因音节边界错位造成虚假代价（如 chang an 与 cha ngan），地址中此类情形常见，所以必须采用两层结构。

## 8. 地址库必须分级

最初考虑将全部地址库注入 system prompt 进行上下文偏置，但规模不可行。参考 Google CLAS 论文结论：上下文偏置在候选数数百至数千条时增益最大，上万条后收益明显收窄。全国 POI 上亿条，直接注入必然退化。
但地址具有严格的树状层级：
全国 → 省(34) → 市(337) → 区县(2843) → 街道/道路/小区(百万级)
若将四级作为独立维度做笛卡尔积，理论组合数为 34×337×2843×347 ≈ 113 亿。而实际合法条目数（各级行政区划代码表）仅约 3561 条（省市区三级）。每条候选沿父链回溯，唯一确定一条完整地址链。层级先验将搜索空间压缩了约 317 万倍，这是一个硬约束，所有不合法组合概率为零。
压缩后候选规模落在 CLAS 推荐的甜区内，此时上下文注入才有实际意义。

## 9. 层级结构支持地址补全

真实录音中出现一条抱怨式语音：
“哎呀，真的烦……你能不能给我寄到那个花牌坊高通巷三十八号碧园公寓？”
说话人全程未提及城市或省份，仅给出街巷名。这在真实场景常见——默认对方知道所处城市。
利用层级库，命中“花牌坊街”条目后，沿 parent 回溯得到金牛区→成都市→四川省，再结合规则抽取门牌号“38号”和保留“碧园公寓”，最终补全为：
四川省成都市金牛区花牌坊街交通巷38号碧园公寓
其中省市区三级来自回溯，街巷名来自语音，门牌由规则抽取，小区名原样保留。需要强调的是，回溯出的父链不应计入证据强度，打分时必须区分命中层级与补全省级，避免高估置信度。

## 10. 覆盖率问题的暴露

省市区三级可离线穷举（GB/T 2260，共 3214 条），但街道、道路、小区是开放集，量级百万且动态变化，必须依赖 POI 接口（如高德/百度）。我先建了 347 条精选路级库用于流程验证，但真实录音暴露了覆盖不全的风险：
一条贵阳话录音，模型输出完全正确：“贵阳市云岩区中华中路一百二十号喷水池国贸广场二十三楼”。但我的库里只有中华北路和中华南路，没有中华中路。
拼音距离 中华中路 vs 中华北路 为 0.250，低于阈值，系统将正确答案“纠正”为中华北路并给出高置信度。这说明：当正确答案不在候选集中，任何排序算法都无法选出正确项，三道阈值只防“库内有更似候选”，防不住“库内无正确答案”。因此，街道及以下层级必须接入高德 POI 实时查询，这是覆盖率问题的唯一解法。

## 11. 打分函数设计

对每条候选链，采用线性打分函数：
score(A) = 0.50·sim + 0.20·cov + 0.15·prior + 0.15·depth − 0.25·conflict
各项含义：
sim（音相似度）：各层命中按层级特异性加权平均，权重：省0.6、市0.8、区1.0、街道1.1、路/POI 1.2。越具体的层级命中说服力越强。
cov（覆盖率）：命中片段占输入汉字比例，衡量候选能解释多少输入。
prior（先验热度）：链上各条目的热度（POI访问量、人口密度、历史下单频次）。
depth（证据条数）：取 min(命中数, 3)/3，注意回溯出的父链不计入。
conflict（冲突扣分）：若输入中有另一条强命名的行政区（省/市/区）不在当前链上，则扣分。注意：路级不参与冲突计算，因为同一区内的不同路名是互相印证而非冲突（第一版误将路级算入，导致渝中区“解放碑”与“民权路”互相扣分，正确答案跌出前三）。
以上权重为手设，暂未拟合。后续应使用标注数据做 learning to rank（如 MERT 或结构化感知机）进行权重学习，再通过保序回归校准为真实概率。
以第 9 节的抱怨录音为例：
sim = 0.967（花牌坊 1.000，交通巷 0.933 加权平均）
cov = 0.207（29 个汉字命中 6 个）
prior = 0.750（链上四级条目加权热度）
depth = 0.667（2 条证据，min(2,3)/3）
conflict = 0（无其他行政区强命中）
总分 = 0.50×0.967 + 0.20×0.207 + 0.15×0.750 + 0.15×0.667 = 0.737
覆盖率权重较低（0.20），因为真实语音中大量内容（如抱怨）与地址无关，若覆盖率权重过高，会惩罚说话啰嗦的案例。

## 12. 两音节匹配不可单独作为证据

入库后发现大量两音节地名存在拼音碰撞。统计：2 音节地名（含别名）共 3026 个，去重后仅 2584 个不同拼音串，其中 794 个出现碰撞，占 26.2%。例如 xiangcheng 对应相城区、乡城县、襄城县、项城市、襄城区、芗城区 6 个不同行政区；gulou 对应南京、福州、开封、徐州等多地的鼓楼区。
从信息论看，在 2843 个区县中定位一个，约需 11.5 比特信息量。两个汉字音节提供的实际熵远低于此，因为汉语音节分布不均，地名用字集中。因此，两音节及以下的命中只能标记为“弱命中”，不可单独成链，不可作为冲突扣分依据，不可触发落选删除；只有当同链存在更高层级的强命中时，弱命中才可辅助印证。
进一步细化：若一条链的最深命中是依靠两字别名碰撞获得的，即使父级有强命中，该链也不成立，因为父级强命中无法为任意子级候选担保。例如“阳河”被匹配到唐河县，而“南阳市”是强命中，但无法证明唐河县确实被提及。

## 13. 拒绝决策与阈值设计

最危险的失败模式是自信地答错。我们通过上下文注入实测验证了风险：对一条普通话录音（原正确输出“红牌楼”），在 system 位注入不同误导候选，结果如下：
| 注入内容 | 输出 |
|---|---|
| 不注入 | 红牌楼 |
| 单条误导「红牌坊街道」 | 红牌楼 |
| 误导 + 花牌坊街 | 红牌坊 |
| 误导 + 春熙路 | 红牌坊 |
| 两条都指向红牌坊 | 红牌楼 |
| 仅花牌坊街 | 红牌楼 |

结果表明：注入确实可改变正确结果，但触发条件非线性且不可预测。因此，不能无条件信任二次解码结果，必须引入拒识机制。
采用带拒绝选项的贝叶斯决策，损失高度不对称：
L(送错地址) >> L(让用户确认)
一次错误投递的成本（重新配送+客诉）可能是用户确认操作成本的数十倍以上。因此，最优策略是仅在后验概率足够高时自动决策，否则返回 N-best 让用户选择（Chow 拒识规则）。
具体实现三道确定性闸门：

## 1. 分差阈值：Top-1 与 Top-2 分数差 < 0.06，且两者指向不同行政区 → 判为 ambiguous，返回 N-best 请求确认。若仅指向同区不同道路，不影响送达，不予拦截。

## 2. 相似度阈值：Top-1 的音相似度 < 0.62 → 判为 reject，保留原始 ASR 文本，不做纠正。

## 3. 门牌及以下不纠正：楼栋、单元、室号等细粒度信息只做规则抽取，不从地址库匹配，因为库无法穷举每一扇门。

第三点曾被违反：一条上海话录音输出“南京西路八百一百八号”，旧解析器按累加计算为 908 号，这是错误猜测。现改为带位值校验的解析器，若位值不递减则判为非法，门牌字段留空并标记未核验。

## 14. 当前进展

文本模式评测：24 句朗读稿经后处理，归一化完全匹配 24/24，全部为 confident。该测试仅验证后处理链路，使用完美 ASR 输出。
真实录音：45 条可用音频已进清单（`data/eval/manifest.jsonl`），其中 33 条有真值草稿、4 条是无地址负样本、8 条听不清留空。第 16 节是按评测体系 v2 跑出来的分阶段结果。早期的三个反面案例——① 中华中路被误改为中华北路；② “巴适的板”被带入地址串；③ 澳门因两音节弱命中被误匹配到别的省——现在分别对应第 16 节里的兄弟路守门、结尾闲话切分、唯一音短名放行三处改动，前两条已修正，澳门一条修到了“省级正确、区级库缺”。
草稿真值是按 ASR 输出和文档记载预填的，说话人本人确认前，音频模式的数字只能看趋势。

## 15. 后续优化方向（按优先级排序）

## 1. 权重学习：当前五个权重为手设，应使用标注数据做 learning to rank（MERT 或结构化感知机），再通过保序回归将总分校准为真实概率，从而阈值可依据损失比自动设定。

## 2. 声学似然真值化：当前用拼音加权距离代理声学似然，下一步应接 Qwen3-ForcedAligner 对 Top-K 候选做强制对齐，得到真正的声学似然分数，这对吴语、湘语、赣语等缺乏罗马化库的方言尤为重要。

## 3. 音变代价统计：用带标注方言数据统计混淆矩阵，代价取负对数似然，替换手设值，使距离度量真正逼近对数概率。

## 4. 接入高德 POI 及定位：结合用户 GPS 定位，对半径内道路赋予更高先验，可直接解决库不全导致的错误纠正。

## 5. 区分度代替音节数：将弱命中规则从“数音节”改为“计算名称在全库中的拼音碰撞数”，避免误伤短但唯一的真实地名。

## 6. 使用 n-best 输出：目前仅取贪心解码的一条输出，后续可开启 beam search 获取 n-best 及 token 级对数概率，更准确捕捉模型不确定性。

## 16. 评测体系 v2 落地与后处理调优（2026-09-10）

不微调，ASR 的错误分布就是固定输入，能改的只有后处理。按《评测体系设计.md》把 `eval/run_eval.py` 从“一个总分”扩成了分阶段、分片、带负样本与 oracle 上限的评测，然后用它暴露出来的错例反过来改后处理。每一步改动都过了回归（`eval/regression.py`，24 句 text、oov 负样本、720 条合成扰动逐分片比，任一分片退化即失败）。

### 16.1 评测体系做了什么

| 部件 | 文件 | 作用 |
|---|---|---|
| 六段打分 | `eval/stages.py` | A 裸 ASR（字级/音级 CER、地名片段可恢复比例）、B 归一化（方言词、口语数字、门牌四字段、非法数串、闲话泄漏）、C 召回（真值链是否进候选，未召回的原因）、D 排序（Top-1 是否真值链、MRR、排错时五项分数差谁占主导）、E 闸门（TP/FA/FR/TR 四格、是哪道闸门放行或拦截）、F 补全（回溯的省市区对不对） |
| 归因决策树 | `eval/attribution.py` | 每条错例只贴一个标签：db_missing → asr_unrecoverable → normalize_error → recall_miss → rank_error → gate_over_accept / gate_over_reject → completion_error → assembly_error，顺序即上游优先 |
| 负样本 | `data/eval/negatives/` | 库缺（临时删 10 条有近音邻居的条目，测过度纠正）、ASR 已对（裸转写地名已对的子集，任何改动都是改坏）、注入（六种上下文注入条件固化，两条 known_flip） |
| 合成扰动 | `data/eval/synthetic/perturbed.jsonl` | 用代价矩阵反向生成 720 条错字文本，27 条规则可回放；只能测排序/闸门/门牌/补全，不能验证代价矩阵本身 |
| oracle | `--oracle db,rank,gate` | 把库、排序、闸门各换成完美的，看端到端还能推多少 |
| 阈值重放 | 报告第 3 节 | 存下每条样本的 Top-1/Top-2 总分、相似度、覆盖率，在 MARGIN_MIN × SIM_MIN 网格上重放闸门画 risk-coverage 曲线，不重跑检索 |
| 配对统计 | 报告第 4 节 | 同一段音频 baseline（第 1 遍裸转写 + 数字归一化）对 audio 的纠正四格，bootstrap 区间 + McNemar |
| 回归与 CI | `eval/regression.py`、`eval/golden/`、`.github/workflows/eval.yml` | 库 / 代价矩阵 / 权重 / 阈值 / 拼装任一改动都跑，快照更新是显式动作 |

样本量：24 句朗读稿 + 33 条有草稿真值的录音，任何分片都不到 150 条，报告里每个百分比旁的 Wilson 区间都很宽，n < 20 只报 k/n。校准集与权重学习集为空（未达 300 / 500 门槛），报告只画 reliability 图不做保序回归。

### 16.2 评测暴露了什么

调优前，三份集合上的错例归因：

| 集合 | n | 错例 | 归因 |
|---|---|---|---|
| 朗读稿 text | 24 | 0 | — |
| 库缺负样本 oov | 10 | 过度纠正 2 | db_missing 2（天府三街→天府一街，同区兄弟路从分差闸门的“同区豁免”里漏过去；犀浦镇→犀浦街道无法规范） |
| 合成扰动 | 720 | 30 | normalize_error 21、assembly_error 5、rank_error 4 |
| 录音 audio | 33 | 11 | db_missing 6、gate_over_accept 5（全是结尾闲话泄漏）；裸 ASR 已对的 21 条里被改坏 3 条 |

合成集的 30 条错例回溯到底只有三个原因，这是分阶段评测的价值所在——按端到端看只知道“错了 30 条”，按阶段看知道该改哪一行：

1. **别名抢戏**（rank_error 4 + assembly_error 5 + normalize_error 一半）。`best_window` 在同一条目的多个名字里取距离最小的：“浓泉驿区大面街道龙泉大道”里 龙泉驿区 的 2 字别名“龙泉”在“龙泉大道”上距离 0，把本该落在“浓泉驿区”（距离 0.01）的区级命中拽到了路名上——区变成弱命中、链上没了区、还多出一条冲突。“天府新区”“花溪区”同理。
2. **被听错的类型后缀漏出来**（normalize_error 大半）。“春熙路朴行街”：别名“春熙路步行街”距离 0.026，正名“春熙路”距离 0，取了正名，剩下的“朴行街”当成未核验地名原样输出。
3. **命中名字的开头被听错**：“航空路一号称都双流机场”，别名“双流机场”命中后输出全名“成都双流国际机场”，前面的“称都”留成了未核验片段。

录音集的 5 条闸门放行全是同一件事：门牌之后的闲话（“老火锅馆，巴适的板”“地道甘肃味儿”“本地腔说”）和店名在同一个自由段里，逗号没切开，一起留下了。

### 16.3 改了什么

全部改动在 `rank.py` 与 `pipeline.py`，无一处动模型：

| 改动 | 修的是 | 对应错例 |
|---|---|---|
| 同一条目更长的名字距离不比最短的差 0.08 以上就用更长的（`LONGER_NAME_TOL`） | 别名抢戏；顺带把“春熙路朴行街”“磁器口居镇”“茶店子斯街”整体命中到长别名 | 合成集 2/3 的错 |
| 兄弟路守门 `is_sibling_mismatch`：命中窗口只在方位/序数字上有代价 ≥ 0.9 的替换 → 不命中、名字原样保留 | 中华中路 vs 中华北路、天府三街 vs 天府一街——两个音毫不相干，说的就是库里没有的那条 | oov 过度纠正 2→0；录音改坏 3→0 |
| 省/市的 2 字简称全库拼音唯一且几乎精确命中时不按弱命中处理（方案 §15.5 的“区分度代替音节数”，只放行省市级） | 澳门 → 从“安徽省淮南市大通区”变成“澳门特别行政区 …（partial）” | 录音 210150 |
| 孤证闸门：整句只有一处近似命中且覆盖率 < 0.25 → reject | “用那个闽南话再说一个地址呢也是……”撞出讷河市 | 无地址负样本 |
| 冲突只看路级证据之前、以及最深行政区之后不再冒出的更浅一级 | “皮铺还是”撞出珠海市、“北盛购物中心”撞出湖北省，把正确链压成 ambiguous | 录音多余确认 2→0 |
| 繁→简（opencc，可选依赖） | 粤/闽录音吐繁体，“龍頭路八十九號”号不认、路匹配不上 | 录音 213038 |
| 自由段先按标点和口语填充切开再逐段判断；门牌之后带“的/嘅”或“地道/味儿/腔”的段是闲话；夹在省与市之间的自由段是闲话 | 结尾闲话泄漏 | 录音 5 条闸门放行 |
| 落选竞争行政区只删门牌之前的；命中后紧跟的“路/街/巷/道”并入名字（中街+路）；命中名字被听错的开头/结尾（“称都”对“成都…”，多音字取最像的读音）被吸收而不是留成未核验 | 拼装 | 合成集 017、录音 中街路 |
| reject 时不用候选链拼装，原文交出去（与音频路径一致） | 文本入口的契约 | — |

### 16.5 现在能说和不能说的

能说的：后处理的净收益方向是确定的（bootstrap 区间不跨零），改坏率在这批录音上是 0，库缺是主要剩余错因，评测每个分片都能定位到具体环节。

不能说的：任何带置信区间的错送率。33 条录音的 risk 3.2% 的 95% 上限是 16.2%；要说“错送率 ≤ 2%”需要每个分片 150 条零错。录音真值还是草稿，要说话人本人过目改成 confirmed。样本缺口按报告第 1 节的表补：官话之外每个音系都只有个位数，`street_only` 只有 2 条。

技术债照旧登记：分差闸门“同区不同路不拦”的豁免与投递等价的定义矛盾（设计 §3 待议），这次靠兄弟路守门绕过了它暴露出的那个案例，规则本身没动；注入带偏的两个条件仍是 known_flip；五个权重和三道阈值仍是手设。

## 17. 参数从数据里学、评测自己能自检（2026-09-10 下午）

§16 的评测是一把量尺，但后处理参数还写死在代码里，改进也是人读归因表后手改的。这一节回答两个质疑：**新数据进来后参数能不能自动重新拟合**，以及**"评测够不够全面"有没有证据**。原则先定死：闭环自动出提案，人执行 apply 才生效；不微调模型。

### 17.1 参数成为数据

五个权重、三道阈值、四个检索常量搬进 `data/params/rank_params.json`，带版本、来源（hand-set / tuned / tuned-below-threshold）、创建日期、数据快照指纹和历史。`rank.py` 导入时加载，模块属性名不变，评测、`--set` 故意破坏、全部测试原样可用。服务的 `/api/status` 和页面状态条报参数版本与代码提交号——这是之前分不出 8850 与 8851 新旧的那个缺口。

### 17.2 闭环怎么转

打分函数的五项分量不依赖权重，决策只依赖总分、相似度、分差和阈值。所以检索只跑一次（`eval/features.py`，791 条约 2.5 分钟，存下每条样本全部候选链的分量），之后任意一组参数在 `eval/rescore.py` 里 0.02 毫秒重放三道闸门。`eval/tune.py` 在训练片上做坐标下降加 20 次随机重启，目标是损失比 10 : 1 的平均代价加一项 L1 拉回手设值；留出片上查六条硬约束；`--confirm` 用候选参数真跑四份评测和回归，量化重放与真跑的偏差；`--apply` 只在 verdict 为 APPLICABLE 时写新版本。划分按 `splits.json`：合成集按句分组不跨集，有效样本按句计。

### 17.3 今天跑出来的诚实结果

| | |
|---|---|
| 训练片有效样本 | 12 句 / 门槛 500；校准片 6 / 300 |
| 提案参数 | 与手设完全一致 |
| 可辨识表 | 8 个可重放参数在训练片上全部"平"：SIM_MIN 和孤证阈值在整个区间内目标不变，W_CONFLICT 在 [0, 0.29] 不变，MARGIN_MIN 在 [0, 0.09] 不变 |
| 重放与真跑偏差 | 朗读稿 0/24，合成 0/720，库缺 1/10，录音 3/37 |
| 校准 | calib 180 条全部 confident，ECE 0.06 → 0.0；未达门槛只报不存 |
| verdict | REPORT_ONLY（sample_gate） |

这就是第 15 节第 1 条"权重学习"在今天数据上的真相：目标函数是平的，724 条文本样本全部正确，任何保持它们正确的参数代价都是 0。闭环没有"学到"新参数，它给出的是每个参数被数据钉住了多少。这比一组看起来学出来的新值有用：它说明下一步不是调参，是补数据——训练片有效句数要从 12 到 500，各难点标签各 30 条。

录音上 3/37 的偏差来自两个已知近似：正确与否按"Top-1 链是真值链"算，拼装漏出来的闲话不在环内；真值路级不在库里时用"库条目是所说地名的子串"近似过度纠正。这两个数字写在每份提案头上。

### 17.4 评测自检

`eval/selfcheck.py` 对每个归因标签构造一种故意破坏，断言评测贴出预期标签。12 个场景全部通过，1 个标签（completion_error）被证明按构造不可达。它还找出四件事：

- 朗读稿对 `W_CONFLICT=1.0` 毫无反应，只有合成集能让回归变红，而且只靠 1 条样本。权重的可辨识性建立在个位数样本上。
- 文本与合成集的 Top-1 音相似度几乎全是 1.0，SIM 闸门在 0.62 附近看不见任何东西，只有音频集（最低 0.83）能测它。
- `completion_error` 之前可达，但唯一路径是误归因：库缺、地名原样保住、闸门正确拦下、省市无从回溯，被记到补全头上。归因树第 2 步补了这条路径，现在记 db_missing。真正的补全错按构造不可达。
- 召回只看真值链最深层：市、区、街道层被扰动没召回时，扰动字原样留在输出里被记成闲话泄漏。这是归因树的已知盲区，登记待改。

收尾那张"能抓住什么、抓不住什么、需要什么数据"的表在 `eval/selfcheck/latest.md`，CI 每次改动都重跑。

### 17.5 现在的边界

参数落地要等训练片有效句到 500，这个门槛不是拍的，是 §2.6 的置信区间要求。合成集由同一代价矩阵生成，只能约束下游，仅靠它的提案永远进不了 apply。录音真值 32 条草稿、9 条待填，说话人确认前 `--strict` 会把它们排除在调参之外。新录音的路径是 `scripts/intake.py`，到"说话人填真值"那一步必须停下来等人。
