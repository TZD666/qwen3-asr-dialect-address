# Qwen3-ASR-1.7B 方言地址识别 · 技术方案与思路

> 目标：用 Qwen3-ASR-1.7B 做方言语音的地址识别。
> 组成：可录音的测试界面（`demo/`，8850 端口）、代码（约 4.8k 行，核心 `src/dialect_addr` 约 2.7k 行）、本文档。
> 一句话结论：这不是一个"把 ASR 调准"的问题，而是一个"给 ASR 补上地址先验"的问题。模型只负责听音，地址库负责定字，所有关键判断走确定性代码，模型的输出永远可以被推翻但不能被吞掉。

---

## 一、看到题目时是怎么想的

### 1.1 先把问题定性

ASR 做的事是 `argmax P(文字 | 音频)`。我们要的是 `argmax P(真实地址 | 音频)`。展开一下：

```
P(A|x) ∝ P(x|A) · P(A)
           ↑声学似然   ↑地址先验
```

ASR 只有前一项，后一项它用的是通用中文语言模型的先验。地名是长尾专名，"武侯区"在通用语料里的频率远低于"五后区"这种常见字组合，所以模型在声学模糊时会倒向常见字。这不是它"听错"，是它的先验在这个领域是负作用。

由此得出第一个判断：**解法不是修 ASR，是把 P(A) 补进来。** 补的来源有三个：地址库（哪些地址真实存在）、层级约束（路必须在某个区里）、用户定位（可选）。

### 1.2 方言误识有一个可利用的性质

对比真值和误识：

| | 内容 | 拼音 |
|---|---|---|
| 真值 | 成都武侯区红牌楼 | wu hou qu hong pai lou |
| ASR | 成都五后区红排楼 | wu hou qu hong pai lou |
| 汉字编辑距离 | 3 | 拼音编辑距离 **0** |

**错的是字，音基本还在。** 这决定了匹配要在"音的空间"里做，不在汉字空间做。汉字空间里这两句看着全错，音的空间里它们是同一句话。

### 1.3 为什么走零训练

三个理由，按重要性排：

1. 问题的本质是先验缺失，不是声学能力不够。1.7B 模型在 22 种方言上训练过，它的编码器已经懂这些方言的音。再训练是在解决一个不存在的问题。
2. 没有方言地址的标注数据。微调需要数据，1-2 天的节奏里凑不出来，凑出来了也会有灾难性遗忘的风险。
3. 外挂方案对模型版本不敏感。将来换 3B、换云端 API，这套后处理照样用。

零训练不是妥协，是对问题的判断：**能用检索解决的，不要用训练解决。**

### 1.4 一开始就定下的三条红线

- 门牌、楼栋、单元、室号绝不从地址库猜。库里不可能穷举每一扇门，这部分只能从语音里听出来，按规则转写。
- 层级合法性是硬约束不是软分。"成都市 + 江北区"这种候选根本不允许被构造出来。
- 最危险的失败不是识别不出来，是**自信地答错**。宁可吐 N-best 让人确认，不能把说对的地址"纠正"成库里那个相似但错的。

## 二、看了模型的方言表现之后，想法怎么变的

方案不是一次设计出来的。下面按时间顺序记录每次实测之后设计发生了什么变化。所有条目都是 2026-09-09 当天在 Apple M5 Pro / MPS fp16 / transformers 5.16.1 上实测的。

### 2.1 权重布局：决定不用官方包

官方发了两套权重，`Qwen3-ASR-1.7B` 是 qwen-asr 包和 vLLM 用的 `thinker.*` 布局，transformers 原生类加载不了。写了 `scripts/convert_to_hf.py` 做纯键名重命名，708/708 个键加形状双重校验。

这个选择的意义不只是省一份 4.7GB 下载。**原生后端让我自己拼 messages，system prompt 完全可控**，这正是后面两遍解码要用的口子。官方包把这层封死了。

### 2.2 输出格式与粤语：词汇归一层从"可选"变成"必需"

实测输出是 `language Chinese<asr_text>正文`，语种标签在前。喂粤语进去，标签是 `Cantonese`，**正文输出的是粤文**："我住喺广州市天河区……"。

这意味着方言差异不止发音，还有词汇。地址领域用到的方言词是封闭集：居所词（屋头、屋企、阮兜）、方位词、量词、语气词（噻、咧）、数字读法。几十到几百条的量级，所以做成确定性查表（`dialect_lexicon.py`，79 条词表 + 10 组字形变体），不交给模型猜。

### 2.3 上下文注入：最重要的一条证据

开源版 README 里没有"context"字样，这个能力是从 `chat_template.jinja` 的结构推断的：system 位是自由文本，直接进 Qwen3 解码器。必须实测。

| 注入内容 | 输出 |
|---|---|
| 正确候选「红牌楼」 | 不变（本来就对） |
| 单条误导候选「红牌坊街道」 | 不变（顶住了） |
| **误导候选 + 另一个指向别处的候选** | 从「红牌楼」变成了「**红牌坊**」 |

这一条同时证明了两件事：**system prompt 里的候选确实会改变开源 1.7B 的解码结果**，所以两遍解码这条路是通的；**模型会顺着候选把听对的改错**，所以幻觉性纠正的风险是真的。

触发条件不规律，单条误导候选顶得住，两条指向不同地点时反而翻车。六组对照的原始记录在 `eval/reports/context_injection.json`。（早期记录写的是"单条即翻"，2026-09-09 复跑未复现，已更正。）

设计上的直接后果：第二遍的结果不能无条件采信，要和第一遍比决策等级再择优；打分层的三道阈值不是摆设。两遍解码做成可开关，实测不通就退回纯外挂重排，方案不依赖它成立。

### 2.4 第一条真人四川话录音：两个漏洞

说的是「成都市花牌坊交通巷38号碧园公寓2栋4单元603」。第一遍裸转写：`成都市花牌坊高通巷三十八号碧园公寓二栋四单元六零三`。

**漏洞一：音变矩阵漏了见系不颚化。** 交 jiao 被听成 gao，这是西南官话最典型的音变之一（街=gai、鞋=hai、交=gao），第一版矩阵只收了 n/l、平翘舌、h/f、前后鼻音。补入 g/j、k/q、h/x 三对声母和 iao/ao、ie/ai、ia/a 三对韵母后，交通巷与高通巷的距离 0.067，命中。

**漏洞二：拼装层会吞掉没命中的地名。** 第一版是"从候选链生成"，只输出命中的层级。地址库里没有"碧园公寓"，它就消失了，用户看到 `四川省成都市38号2栋4单元603室`。改成**以 ASR 原文为锚**重建：命中段换规范名，缺失的上级行政区补插，**没命中的段原样保留并标"未核验"**。同时新增 `partial` 决策等级：只命中省市级不再算 confident。

原则从这里明确下来：**宁可把没核验的原文交出去并标明，也不能悄悄吞掉。**

### 2.5 全国表入库：库大了之后的四条规则

手工精选 27 个城市在真人测试里立刻穿帮（"南阳市卧龙区"落空）。改为全国 34 省 / 337 市 / 2843 区县全量入库，路级仍是精选 347 条。

库大 6 倍后暴露的问题全是**2 字名撞车**："中山路"的中山撞中山市、"广场"撞广昌县（guang chang）、"河南话"的南话撞南华县。四条规则：

| 规则 | 内容 | 挡住的案例 |
|---|---|---|
| 弱命中 | ≤2 音节的命中不能单独成链、不当冲突扣分 | 中山市 / 广昌县 |
| 别名不担保 | 链的最深命中若靠 2 字别名撞上，父级强命中不能替它担保 | 唐河县 ← "阳河" |
| 孤立路名须精确 | 没有行政区锚定时，路名距离必须 ≤0.15 | 民权路 ← "人民路" |
| 方言/籍贯后缀 | 别名后紧跟 话/腔/人 不算地址 | 河南省 ← "河南话" |

副产品：全国重名区（鼓楼区×4、西湖区×2）只说区不说市时正确地弹 `ambiguous`，说了市就分开。

### 2.6 上海话录音：门牌解析也会"自信地答错"

上海话录音，模型两遍都吐出「南京西路八百一百八号」。这不是合法的中文数字，两个"百"连出现，是听错或幻觉。旧的数字解析器是纯累加器，算成 800+100+8 = **908 号**，自信地写进门牌字段。

这条暴露的是**我自己的红线没守住**：门牌不从库猜，但解析器在猜。改成带校验的位值解析：位值不递减、万重复、非零数字相邻，任一命中就判非法，原文原样保留标未核验，门牌字段留空。顺带补了口语补位（八百八→880，一百五→150，有"零"才是个位）。回归用例在 `tests/test_normalize.py`。

### 2.7 与模型无关但会让人误判的坑

- 机器上装了 BlackHole 之类的虚拟音频设备时，浏览器把它当默认输入，录出来全是零，模型返回空串。看起来像"识别不准"，其实是没收到声音。界面现在显示当前输入设备和实时电平，自动跳过虚拟设备，两路采集都静音时直接给诊断。
- MPS 上 processor 输出的梅尔特征是 float32，模型是 float16，`generate` 前要手动 cast，否则第一层 conv2d 报类型不匹配。

## 三、架构是怎么搭的，为什么这么搭

### 3.1 流水线

```
音频
 ↓  Qwen3-ASR 第 1 遍：裸转写 + 方言标签
粗文本
 ↓  dialect_lexicon   方言词 → 标准中文（喺→在、屋头→家）
 ↓  normalize         口语数字 → 阿拉伯数字；剥离门牌/楼栋/单元/室；非法数串原样保留
地名部分 + 门牌字段
 ↓  romanize          按方言选音系空间（拼音 / 粤拼 / 台罗）
 ↓  rank              滑窗对齐找命中 → 自底向上回溯父链 → 打分 → 决策
候选链 Top-K
 ↓  Qwen3-ASR 第 2 遍：把 Top-K 写进 system prompt 重新解码（可开关）
 ↓  取两遍中决策更强的一方
规范地址 + 结构化字段 + N-best
```

### 3.2 每一层的设计动机

**pinyin_dialect：音节级加权编辑距离。** 光转拼音不够，方言音变是系统性的，标准 Levenshtein 把每个替换算代价 1，会把"n/l 不分"这种规律性音变误判成"差很远"。所以是两层距离：外层音节序列做对齐，内层音节间距离 = 声母代价 + 韵母代价，各查一张混淆表（目前 20 条声母、26 条韵母，每条带代价和适用方言区）。比把整串拼音拼成字符串再算准得多，后者会因为音节边界错位产生大量虚假代价（"chang an" vs "cha ngan"）。

**romanize：按音系路由，不是一套拼音打天下。** 模型卡列出 22 种方言。普通话拼音的隐含前提是"方言 = 普通话的音变"，这对官话系成立，对粤语根本不成立：粤语有 -p/-t/-k 入声韵尾和 6~9 个声调，普通话一个都没有。拿普通话拼音量粤语误识等于用错坐标系。所以三分：

| 类别 | 方言 | 音系空间 |
|---|---|---|
| 官话系（12）+ 过渡区（2） | 四川 贵州 云南 湖北 河南 陕西 甘肃 宁夏 东北 河北 天津 山东 山西 安徽 | 普通话拼音 + 方言音变矩阵 |
| 非官话·有库（4） | 粤语港 / 粤语广 / 闽南 / 福建 | 粤拼 / 台罗 + 各自的懒音矩阵 |
| 非官话·无库（4） | 吴 浙江 湘 赣 | 普通话近似（弱信号），靠上下文注入兜底 |

方言库全是可选依赖，没装就把对应路径标记不可用并降级。生产环境里少数派方言的库经常装不上，主链路必须活着。

**实测状态（2026-09-10）**：台罗（taibun）已装并验证可用；**粤拼（pycantonese）因本机网络问题始终没装上，粤语实际走的是「普通话拼音·粤语近似」降级路径**。降级机制本身验证有效，`/api/status` 会报出 `粤拼 available=False, reason=pycantonese 未安装`。因此文档里那条粤语录音的正确结果来自降级路径，粤拼的增益尚无数据。

**dialect_lexicon 与 normalize：封闭集与纯规则。** 这两层没有一行调用模型。方言词是封闭集，查表比模型可靠；门牌数字是"唯一不能靠地址库检索的部分"，规则转写比模型可靠。关键路径上能用确定性代码的地方，不用 prompt。

**address_db：全国三级全量 + 路级精选 + POI 接口。** 省市区 3214 条来自 GB/T 2260 的 adcode 表，含经纬度。路级全国穷举不现实，只能靠 POI API（高德/百度，接口已留）。库里没有的路、小区，按原文保留标未核验。

**rank：先验落地的地方。** 打分函数：

```
score(A) = 0.50·音相似度 + 0.20·文本覆盖率 + 0.15·地址先验 + 0.15·证据深度 − 0.25·行政区冲突
```

音相似度是 P(x|A) 的代理，在该方言的音系空间里算；地址先验是 P(A)，接 POI 热度 / 用户定位 / 历史频次；证据深度表达"匹配到路级比只匹配到市级可信"。候选链一律由"路→区→市→省"回溯父链生成，天然合法。

三道兜底：Top-1 与 Top-2 指向不同行政区且分差 < 0.06 → `ambiguous`，吐 N-best；Top-1 音相似度 < 0.62 → `reject`，保留原文；门牌以下不经过本模块。

**asr：两遍解码，retrieve-then-rescore。** 第一遍裸转写找到 Top-K，第二遍把 Top-K 写进 system prompt 让模型把声学上模糊的部分往候选靠。这是唯一一个"让模型参与纠错"的环节，所以它的结果要和第一遍比决策等级再择优，并且整个开关可关。

**pipeline：每一步中间结果都保留。** Result 里有 pass1、pass2、final、chosen 和每一遍的 raw_text / lex_text / norm_text / tail / ranking。出问题时要能回答"哪一步把它弄错的"。

**demo 与 eval：为演示和为回归各做一件事。** 界面顶部是两栏对照，左「原始模型」= 第 1 遍裸转写（无 system prompt、无语种强制、不连地址库），右「改造后」= 本方案输出。每次录音自动落盘到 `data/eval/audio/recordings/`，既是留档也是在积累评测集。评测不只报 CER：`201室→202室` 只错 1 字符但快递彻底送错门，所以主指标是字段级 exact-match 和归一化完全匹配，按 11 个难点维度分层，另报错误严重性分级。

### 3.3 一句话总结取舍

模型负责它擅长的（听音、方言音系），代码负责它不擅长的（先验、层级、数字、决策）。每个"必须实测"的假设都实测了再写进方案，每个红线都有对应的确定性代码而不是 prompt 里的一句"请不要猜"。

## 四、交付了什么，结果如何

| 交付 | 内容 |

### 4.2 结果（只写实测过的）

|---|---|
| 归一化完全匹配（EM） | **100%**（24/24） |
| 行政区三级全对 | 100% |
| 门牌以下全对 | 95.8%（1 条室号） |
| 决策分布 | confident 24 |

**模拟方言误识**（把"武侯"改"五后"、"花溪"改"发溪"、"南岸"改"兰岸"等 12 条喂进去）：12/12 Top-1 正确，12/12 confident。

**真人录音**（有完整记录的两条）：

| 录音 | 第 1 遍裸转写 | 最终输出 | 决策 |
|---|---|---|---|
| 四川话 | 花牌坊**高通巷**三十八号碧园公寓二栋四单元六零三 | 四川省成都市金牛区花牌坊街**交通巷**38号碧园公寓2栋4单元603室 | confident |
| 上海话 | 南京西路**八百一百八**号 | 上海市静安区南京西路八百一百八号（门牌留空，标未核验） | 不猜 |

**性能**（M5 Pro / MPS fp16）：权重加载 0.9~2.9s，单句推理 0.4~2.2s。

### 4.3 没有的数字，也写清楚

- **24 句评测集的真实音频评测还没跑。** 界面上今晚积累了 47 条临时录音，但都是随手测试，没有对上编号的标注。`--mode baseline` 与 `--mode audio` 的对照表要等按录音指南录完 24 句才有。这是当前最大的空白，也是下一步第一件事。
- 吴语、浙江、湘、赣四个方言没有成熟罗马化库，音系路径只是普通话近似，没有单独评测。
- 声学重打分（Qwen3-ForcedAligner）只是方案里的设想，仓库里没有对应代码。
- 模拟方言误识 12/12 那次测试是在交互里手工喂的，仓库里没有可复现的脚本。

---

## 五、还能怎么改进

按"补哪一块最值"排序。

**1. 先把真实音频的数字拿到。** 录 24 句，跑 baseline 与 audio 对照，得到"裸模型 vs 改造后"在真实方言语音上的字段级差距。方案的说服力现在靠文本模式和两条真人案例，这一步之后才是完整的。

**2. 声学重打分接入。** 用 Qwen3-ForcedAligner（0.6B）对 Top-K 候选做强制对齐打分，拿到真正的 P(x|A) 而不是拼音距离这个代理。这是方言无关的终极兜底，对吴语、浙江、湘、赣这四个没有罗马化库的方言尤其重要。

**3. 用模型自己的 N-best 替代文本重排的一部分。** 现在第一遍只取 greedy 输出。开 beam search 拿 n-best 和 token logprobs，候选生成和音相似度都能更贴近模型的真实不确定性。

**4. 路级与 POI 覆盖。** 接高德/百度 POI 接口，配合用户定位把 P(A) 里的"地址先验"从占位做实。定位半径内的路名优先，是最便宜也最有效的先验。

**5. 阈值与权重用真实数据校准。** 0.06 / 0.62 和 0.50 / 0.20 / 0.15 / 0.15 现在是手设的，评测集够大之后做网格搜索，并按方言分别校准。

**6. 门牌的交互式确认。** 数字非法或置信度低时，界面引导用户逐位复述（"幺零幺"），比任何解析规则都可靠。同时评测集里多放带"零"的门牌，盯住方言里"零"轻读被吞的情况。

**7. 有数据之后再考虑训练。** 界面录音会持续积累，标注够几千条之后，可以在解码器上做轻量 LoRA 或热词偏置（contextual biasing）。但前提是先证明零训练方案的上限在哪，不要为了训练而训练。

**8. 部署形态。** 现在是单机 MPS。生产要么 vLLM 批量推理，要么云端 Qwen3-ASR-Flash API（它原生支持 context 注入），后处理层不动。
